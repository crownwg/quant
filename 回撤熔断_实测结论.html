一句话结论

机制是好的（真能压回撤），但参数不可迁移，别照抄。
训练段 20 组熔断里 16 组跑赢基线，换到没见过的验证段后 0 组跑赢。 训练段的排名和验证段零相关。

要用的话：阈值别低于 25%，并且必须先在没见过的时间段上验证过。

实现时踩的三个坑（已修，有测试锁着）

这类「状态机 + 路径依赖」逻辑写错了不报错，只表现为「净值怎么一直平的」。

1. 清仓后净值冻结 → 永久空仓

降到 0 仓后组合净值不再变化，回撤永远停在触发点，恢复条件永远不成立。 实测「跌 10% 清仓」1623 天里熔断了 1606 天，收益 −13%。 → 恢复要看影子净值（不熔断会走成什么样），不能看自己那个冻结的净值。

2. 恢复判据不能是「距历史高点还有多远」

这个池子 6 年跌 67%，影子净值相对历史高点永远回不来，等于还是永不恢复。 → 改成「从熔断后的低点反弹了多少」。

3. 恢复后立刻再次触发

清仓期间净值冻结在 −30%，不重置高点基准的话，恢复完第二天马上又被打回熔断， 恢复只维持一天。→ 每次熔断后重新起算观察起点。

根因还有一层：「是否触发」只能在未熔断时检查， 否则清仓后它恒成立、恢复分支永远走不到。

怎么用

命令行

--dd-brake 0.30          # 从高点跌 30% 就降仓
--dd-brake-action 0.0    # 降到多少：0=清仓，0.5=半仓
--dd-brake-resume 0.15   # 不减仓的话市场从低点反弹多少才回来（默认阈值一半）

网页

左侧「仓位管理 · 择时 / 风险」里，波动率目标下面新增了回撤熔断三个输入框， 填百分数即可（填 0 = 关闭）。

注意：walk-forward 验证不了熔断——每折测试段只有半年、净值从 1.0 重开， 最深回撤也够不到 30% 阈值，两次跑出来结果逐位相同。 要验证请用时间分割（前几年选参、后几年验证），就像上面这张表做的那样。

同一轮顺带做的另外两件事

一键今日清单

页面「调仓清单」里新增 ⚡ 一键今日清单：自动补数据并把基准日对齐到最新交易日， 不用再管那个默认 20240909 的结束日期。原来的按钮改名为「用指定日期生成」， 留着做历史回放。数据落后今天 7 天以上会单独告警。

自选组合预设

「额外补充代码」下面新增下拉：内置 5 组（老登组合 / 消费白马 / 工程机械 / 白酒 / 金融蓝筹）， 也能把当前填的存成自己的预设。提示：股票池非空时是取并集， 只想跑预设那几只就把股票池清空。

全部为历史回放结果，不是预测、不是买卖建议。 换标的、换时间段结论可能完全不同——这正是上面这张表想说明的事。
