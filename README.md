# 量化工具 · A 股低频选股回测

> 一个本地跑的 A 股量化回测工具：从数据拉取 → 多池组合 → 多策略对比 → 稳健性检验 → 每日实盘清单，全链路打通。

---

## 这是什么

一套基于 **akshare + pandas + numpy** 的低频选股回测框架。从最初的"60 日动量策略能不能赚钱"到现在，工具链已经覆盖：

| 阶段 | 解决的问题 | 入口 |
|---|---|---|
| **数据层** | 增量拉取 / 本地缓存 / 涨跌停与停牌过滤 | `quant/data.py` 自动 |
| **因子库** | 7 个单因子 + 多因子合成 | `quant/factors.py` |
| **回测引擎** | 次日开盘成交 / 涨跌停 / 复权 / 印花税 | `quant/backtest.py` |
| **组合构建** | 月度调仓 / 换手缓冲 / 可执行性约束 | `quant/strategy.py` |
| **调仓清单** | 100 股整手 / 佣金与印花税 | `quant/rebalance.py` |
| **稳健性检验** | 滚动 / 样本外 / 稳健性 | `quant/rolling.py` |
| **风险归因** | 牛/熊/震荡状态拆分 | `quant/attribution.py` |
| **参数优化** | (lookback × top_n × buffer) 网格搜索 | `quant/grid.py` |
| **样本外验证** | 滚动训练/测试，识别参数过拟合 | `quant/grid.py --walk-forward` |
| **择时 / 仓位** | 趋势择时 + 波动率目标，含样本外选参 | `quant/timing.py --timing` |
| **多策略对比** | 同池子横向 7 策略 + 报告 | `quant/compare.py` |
| **多池组合** | 多池子加权 + 相关性矩阵 + 报告 | `quant/combine.py` |
| **因子中性化** | 剥离行业 / 小市值 beta | `quant/neutralize.py` |
| **因子有效性** | IC / IR / 衰减 / 分组收益 | `quant/factor_eval.py` |
| **每日清单** | 一键生成今日调仓 + 可选 webhook 推送 | `quant/daily.py` |

## 数据层（增量缓存）

**核心设计**（`quant/data.py`）：
- 本地缓存每个股票 `data/{code}.csv`，沪深300 指数 `data/index_{symbol}.csv`
- `_ensure_cached` 决策：①已覆盖直读 ②往后追加（最常见） ③区间无数据则全量重拉
- **不补头**：akshare 的 qfq 前复权以"调用当天"为基点，补头会产生价格跳变——宁可重拉

**验证**：干净起点跑 002475（立讯精密），4 步链路：首次 1 full 2.7s → 延长 1 in_range → 再延长 1 in_range → 同窗口 0 fetch 0.0s。

## 因子库

| 因子 | 函数 | 含义 |
|---|---|---|
| momentum | `factors.momentum(prices, lookback, skip_recent)` | 追涨（涨得越多分越高） |
| reversal | `factors.reversal(prices, lookback)` | 反转（跌得越惨分越高） |
| ma_trend | `factors.ma_trend(prices, short, long)` | 均线趋势（短均线相对长均线） |
| ma_breakout | `factors.ma_breakout(prices, window)` | 均线突破（价格相对均线的偏离） |
| low_volatility | `factors.low_volatility(prices, lookback)` | 低波动异象（波动越小分越高） |
| volume_trend | `factors.volume_trend(volume, short, long)` | 量能（近 short 日均量/近 long 日均量） |
| combine | `factors.combine(factors, weights, method)` | 多因子合成（zscore / rank） |

## 功能详解

### 1. 经典动量回测（最简用法）

```bash
.venv/Scripts/python.exe -m quant.main --codes "600031,000858,002557" \
    --start 20200101 --end 20240909 --use-open
```

输出：`equity_curve.csv`、`metrics.csv`、`rebalance_plan.csv`、可选 `report.html`。

### 2. 股票池自动化（不用手敲代码）

支持的池（`quant/universe.py`）：
- 指数：`hs300`、`zz500`、`zz1000`、`sz50`、`cyb`、`kcb`
- 行业：`消费`、`可选消费`、`医药`、`白酒`、`蓝筹`
- 任意 6 位指数代码（如 `000932`）
- 概念板块：`concept:白酒`
- 全市场：`all`（含已退市个股）

```bash
.venv/Scripts/python.exe -m quant.main --pool hs300 --top-n 20 --use-open
# 多池合并
.venv/Scripts/python.exe -m quant.main --pool "消费,hs300" --top-n 15
# 手动 + 池子混合
.venv/Scripts/python.exe -m quant.main --codes 600031,000858 --pool zz500
```

#### ⚠️ 幸存者偏差与「时点快照」

指数成分股接口返回的是**当前**成分股。用它回溯历史，等于「只在今天还活着的公司里选股」，
当年在指数里、后来被剔除或退市暴跌的股票压根不在池子里，收益会被系统性高估。

本项目用三层机制处理，按推荐度排序：

**① `--pool all`：全市场建池（最彻底）**
```bash
.venv/Scripts/python.exe -m quant.main --pool all --min-listed-days 250 --use-open
```
池子不依赖指数名单，「某股当时能否交易」完全由行情数据（当日有无 K 线）决定，
退市股也在池内，因此**从构造上就不存在幸存者偏差**。
代价是标的数量大（数千只），首次下载慢。

**② `--as-of` + 成分股时点快照**
每次联网拉取成分股都会自动归档到 `data/cons_snapshots/cons_<指数>_<YYYYMMDD>.csv`，
所以从启用之日起会逐步积累可回溯的时点历史：
```bash
.venv/Scripts/python.exe -m quant.main --pool 消费 --start 20220101 --as-of 20220101
```
请求日期早于所有已有快照时会**显式告警**并提示偏差，绝不静默使用有偏数据。

**③ `--min-listed-days`：剔除次新股（便宜的补充）**
```bash
.venv/Scripts/python.exe -m quant.main --pool 消费 --min-listed-days 250
```
上市未满 N 个自然日的股票不参与选股，避开新股连续一字板与「上市前 5 日不设涨跌停」的失真区间。
注意：启用后预热期会自动前移，代价是首次运行要多拉一段历史。

### 3. 滚动回测 / 样本外检验

```bash
.venv/Scripts/python.exe -m quant.main --pool 消费 \
    --start 20200101 --end 20240909 --use-open \
    --rolling --roll-window 504
```

每段 504 个交易日（≈2 年），不重叠；输出 `rolling_curve.csv` + `rolling_metrics.csv`。

**关键发现**：动量策略在 2020-2021 牛市 +70~+100% 但 2022-2024 持续亏损——**总收益好看≠策略稳健**。

### 4. 风险归因（按市场状态拆收益）

```bash
.venv/Scripts/python.exe -m quant.main --pool 消费 \
    --start 20200101 --end 20240909 --use-open \
    --attribution --benchmark sh000932
```

基于基准中期趋势（默认 60 日涨跌幅 ±5%）把每日标为「牛/熊/震荡」，输出每个状态下的策略收益/超额/夏普。

**关键发现**：消费动量在熊市 **跌得比基准少**（-46.6% vs -52.4%），有防御性；沪深300 动量在熊市**跌得比基准还多**（-43.0% vs -38.0%），反而放大风险。

### 5. 参数优化（网格搜索）

```bash
.venv/Scripts/python.exe -m quant.main --pool 消费 \
    --start 20200101 --end 20240909 --use-open --grid \
    --grid-lookbacks 60,90,120,160 \
    --grid-topn 10,15,20 \
    --grid-buffers 0,2
```

24 组网格；输出 `grid_results.csv` + `grid_report.html`（夏普热力图 + 明细表）。
加上 `--grid-timing` 可把择时参数一起纳入搜索（详见 9.1），报告会多一张「择时维度对比」图。

**关键发现**：消费最优 **lb=120, n=10**；沪深300 最优 **lb=160, n=20**——**不同池子的最优参数不一样**，必须 per-pool 调优。

### 6. 多策略对比（横向挑稳健策略）

```bash
.venv/Scripts/python.exe -m quant.main --pool 消费 \
    --start 20200101 --end 20240909 --use-open \
    --compare --benchmark sh000932
```

7 个预定义策略 + 1 个可选对比（`--compare-strategies`），输出 `compare_results.csv` + `compare_report.html`。

| 策略 | 含义 |
|---|---|
| `momentum_120` / `momentum_60` | 120 日 / 60 日动量 |
| `reversal_20` | 20 日反转 |
| `low_vol_60` | 60 日低波动 |
| `ma_trend` / `ma_breakout` | 均线趋势 / 均线突破 |
| `combine_mom_lv` | 动量+低波动合成 |
| `combine_mom_rev` | 动量+反转合成 |

**关键发现（消费池 + 沪深300 池）**：
- `reversal_20` 在两个池都是**绝对收益和夏普都最强**（消费 +56.7% / 沪深300 +140.5%）
- `low_vol_60` 在两个池都是**回撤最小**（消费 -29.4% / 沪深300 -16.0%）
- **跨池"防御 + 进攻"组合**思路成立

### 7. 多池组合配置

```bash
.venv/Scripts/python.exe -m quant.main \
    --combine "hs300=reversal_20,消费=low_vol_60,医药=reversal_20" \
    --combine-weights "0.4,0.3,0.3" \
    --use-open --benchmark sh000300
```

每个池子用各自的稳健策略独立回测 → 按权重加权合成 → 输出 `combine_results.csv` + `combine_correlation.csv` + `combine_equity.csv` + `combine_report.html`。

**最优组合**（HS300 reversal_20 + 消费 low_vol_60 + 医药 reversal_20, 0.4/0.3/0.3）：
- 总收益 **+68.3%** / 夏普 **0.61** / 回撤 **-29.8%**
- 超额 **+118.9%** / IR **0.78**

**核心洞察**：**池子数量不重要，关键是每个池子用对的策略**。加错了策略（如白酒 ma_trend）反而拖累。

### 9. 择时与仓位管理

风险归因已经说明问题：策略超额收益全程为正，但**纯多头躲不开 beta**（消费池牛市 +119%、熊市 −47.5%）。
选股解决「买什么」，仓位解决「什么时候在场、在场放多少」——这是两个独立的问题。

**两种互补的工具**

| 工具 | 信号 | 输出 | 作用 |
|---|---|---|---|
| 趋势择时 | 价格相对均线 / 过去 N 日收益 / 均线+斜率 | 0 或 1（可设最低仓位） | 判断「要不要在场」 |
| 波动率目标 | 目标波动率 ÷ 已实现波动率 | 连续（如 0.2~1.0） | 只按风险预算缩放，不判方向 |

两者可叠加（敞口相乘）：趋势决定要不要在场，波动率决定在场放多少。

```bash
# 趋势择时：60 日均线 + 2% 滞回带，用中证消费指数当代理
.venv/Scripts/python.exe -m quant.main --pool 消费 --strategy momentum --top-n 15 --use-open \
    --benchmark sh000932 --timing ma --timing-lookback 60 --timing-band 0.02 --timing-proxy 000932

# 波动率目标：把组合波动压到 15% 附近
.venv/Scripts/python.exe -m quant.main --pool 消费 --top-n 15 --use-open --vol-target 0.15 --vol-floor 0.2

# 叠加
.venv/Scripts/python.exe -m quant.main --pool 消费 --top-n 15 --use-open \
    --timing ma --timing-lookback 60 --timing-band 0.02 --vol-target 0.15
```

**两个必须理解的机制**

1. **因果性**：敞口与目标权重同索引（t 日收盘决定、t 之后生效），信号只用到 `close[t]` 及更早。
   `tests/test_timing.py` 有一条专门的测试——篡改未来的价格，过去任一日的敞口必须一字不变。
   这是择时模块唯一能静默毁掉整个回测的错法：一旦偷看未来，净值会好看得离谱，而别的检查都发现不了。
2. **仓位只在调仓日更新**（`--timing-update rebalance`，默认）。这条是踩坑后加的：
   波动率目标逐日连续变化，直接乘到权重上等于**每天全仓对倒**——实测 1125 次调仓 / **17041 笔订单**，
   成本吃掉全部收益，现实中也不可能执行。改为调仓日更新后订单数降到 1025，换手回到月频量级。

**实测**（消费池 2020-01-01~2024-09-09，momentum/120/top15/次日开盘成交，基准中证消费 sh000932）

| 配置 | 平均仓位 | 总收益 | 年化 | 夏普 | 最大回撤 | 年化波动 | 下单笔数 |
|---|---|---|---|---|---|---|---|
| 无择时（基线） | 100% | 40.42% | 7.51% | 0.422 | −41.32% | 25.76% | 382 |
| 趋势 ma(60日,2%) | 47.0% | **61.85%** | 10.82% | **0.657** | −32.15% | 18.98% | 364 |
| 趋势 ma(120日,2%) | 45.0% | 32.78% | 6.24% | 0.425 | −31.94% | 19.13% | 318 |
| 趋势 ma(200日,2%) | 41.5% | 23.26% | 4.56% | 0.329 | −39.54% | 20.67% | 286 |
| 波动率目标 15% | 68.1% | 0.74% | 0.16% | 0.097 | −37.07% | 17.30% | 1025 |
| ma120 × vol15% | 28.7% | 8.50% | 1.76% | 0.208 | **−22.99%** | 12.53% | 542 |

**怎么读这张表**

- **压回撤和降波动是择时唯一稳定的产出**：任一配置都把年化波动从 25.8% 压到 12.5%~20.7%，
  回撤从 −41.3% 压到 −23.0%~−39.5%。这是机制决定的（仓位小自然跌得少），不是运气。
- **收益能不能保住，高度依赖参数**：ma60 三项全改善（收益 +21pp、夏普 0.42→0.66、回撤 −9pp）；
  ma120 收益掉 8pp、夏普持平；ma200 三项全退步。**同一个策略、同一段样本，换个均线长度结论就翻转**——
  所以「择时有效/无效」这种结论不能只看一个参数。
- **波动率目标在这段样本上是纯负担**：目标 15% 低于该池自身的 25.8% 波动，等于长期只放 68% 仓位，
  而消费池长期上涨（基线超额 +64.9%），减仓直接减收益。
  **目标波动率要接近策略自身波动才有意义**；把 25% 压到 15% 就是长期欠配。

**稳健性检验：ma60 是不是被某一段撑起来的？** 按 250 交易日切 4 段不重叠，各段独立回测：

| 分段 | 无择时 | ma60 择时 |
|---|---|---|
| 2020-04 ~ 2021-04 | +74.4% / 夏普 1.84 / 回撤 −29.3% | +54.0% / 1.53 / −29.3% |
| 2021-04 ~ 2022-05 | −24.5% / −0.98 / −32.3% | **−7.4% / −0.54 / −9.5%** |
| 2022-05 ~ 2023-05 | +4.3% / 0.31 / −20.1% | +3.9% / 0.36 / **−8.4%** |
| 2023-05 ~ 2024-05 | −4.7% / −0.20 / −17.2% | **+6.4% / 0.66 / −5.0%** |

**4 段全部降低回撤，3 段提升收益**，唯一落后的是第一段（2020–2021 大牛市，欠配 20pp）。
不是被单段撑起来的。

**结论与建议**

- 把择时当**风险控制器**用，不要当收益增强器用。它的确定性来自「仓位小 → 亏得少」，不是「预测准」。
- 代理指数影响很大：交易消费池就用中证消费（`--timing-proxy 000932`），比沪深300 贴切。
- **任何参数上线前先用 `--rolling` 在目标池子上分段过一遍**，确认不是只在某一段成立。
- 不要叠加太多层：`ma120 × vol15%` 把回撤压到 −23%，代价是收益只剩 8.5%——过度保守也是一种风险。

### 9.2 不做单点择优：邻域平滑 与 参数集成（只在好区域内）

9.1 的结论是「argmax 挑到的大概率是噪声」。那就别挑了。三种替代方案：

| 方案 | 做法 | 对应的问题 |
|---|---|---|
| **邻域平滑选参** | 先在参数曲面上做一次均值滤波（每个点取「自己 + 相邻档」的训练期均值），再取 argmax | argmax 永远踩到孤立尖峰 |
| **全组合集成** | 干脆不选，把**所有**候选的权重矩阵等权平均后一起持有（一笔净额委托，成本只算一次） | 「我知道哪个参数对」这个假设本身可能是错的 |
| **前 K 组集成** | 先按**平滑分**排序，只在**前 K 组**内等权平均（`--wf-ensemble-k`） | 全组合集成把已知最差的区域也等权持有了，被拖累 |

实现细节（`quant/grid.py`）：

- `_neighbor_map`：邻域 = 各维度在候选序列上**相差不超过 1 档**，且**择时模式必须相同**
  （跨模式是「换了方法」，不是「相邻参数」）。邻域是对称的，有单测锁。
- `smooth_scores`：纯函数，只做邻域均值，便于单测。⚠️ 只有 3 档宽，自身占 1/2~1/3 权重，
  只能抹平 `0.42 vs 0.40` 这种量级的抖动；50 倍差异属异常值，均值滤波拉不下来。
- `ensemble_weights`：**平均权重**而不是「平均各条净值曲线」——后者要 N 份资金
  各付一遍成本，既不可实现也把成本重复计算了。
- `parse_ensemble_ks` / `ensemble_arm_keys`：把 `--wf-ensemble-k 3,5,10,0` 展开成
  多条并列的臂（`ens3`/`ens5`/`ens10`/`ensall`），0 = 全部候选，1 退化为「按平滑分选参」。

**实测（同一段测试窗，唯一差别是「怎么选参数」）**

消费池 2020-01~2024-09 · momentum/120/top15 · 训练 504 日/测试 126 日 · 5 折 · 31 组候选

| 参数策略 | 样本外总收益 | 年化 | 平均夏普 | 最差折回撤 | 正收益折 |
|---|---|---|---|---|---|
| Walk-Forward argmax 选参 | −0.5% | −0.2% | 0.18 | −15.5% | 60% |
| Walk-Forward 邻域平滑选参 | +5.9% | +2.2% | 0.49 | −17.9% | 60% |
| 参数集成（平滑分前 3 组） | **+16.7%** | +6.2% | **0.73** | −8.4% | 80% |
| 参数集成（平滑分前 5 组） | +12.6% | +4.7% | 0.67 | −8.4% | 80% |
| 参数集成（平滑分前 10 组） | +4.1% | +1.6% | 0.32 | −8.4% | 60% |
| 参数集成（全部 31 组等权） | −1.7% | −0.6% | 0.01 | **−8.3%** | 40% |
| 全样本最优固定参数（事后选参） | +20.7% | +7.6% | 0.80 | −8.4% | 80% |
| 默认参数（不调参） | −15.9% | −6.5% | −0.33 | −17.9% | 20% |

逐折明细（同一段测试窗，只换选参方式）：

| 折 | 测试窗 | argmax 选中 | 平滑选中 | argmax | 平滑 | ens3 | ens5 | ens10 | ensall |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 2022-01~2022-08 | ma(40日,2%) | 不择时 | +6.0% | −3.3% | +4.3% | +3.0% | −1.3% | −1.2% |
| 2 | 2022-08~2023-02 | momentum(90日,2%) | dual(200日,0%) | **−5.7%** | **+5.2%** | +6.7% | +6.0% | +3.7% | +3.9% |
| 3 | 2023-02~2023-08 | ma(40日,0%) | ma(40日,0%) | −2.8% | −2.8% | −2.8% | −4.5% | −4.1% | −4.6% |

| 5 | 2024-03~2024-09 | ma(40日,2%) | ma(40日,0%) | +1.5% | +6.2% | +4.6% | +4.3% | +3.3% | −0.3% |

最窄那条集成臂（前 3 组）实际持有了哪几组——这是「集成到底押了什么」的直接证据：

| 折 | 前 3 组的择时模式 |
|---|---|
| 1 | `不择时 + ma(40,0) + ma(40,2)` |
| 2 | `dual(200,2) + dual(200,0) + ma(40,0)` |
| 3 | `ma(40,0) + ma(40,2) + ma(60,0)` |
| 4 | `ma(40,0) + ma(40,2) + dual(40,0)` |
| 5 | `ma(40,0) + ma(40,2) + dual(40,0)` |

15 个席位里：**ma 10 席、dual 4 席、off 1 席、momentum 0 席**。

**怎么诚实读这两张表（容易被误读，所以拆开说）**

1. **唯一能下定量结论的，是「K 的单调性」。**
   总收益随 K 增大**单调下降**：16.7% → 12.6% → 4.1% → −1.7%；
   平均夏普同向：0.73 → 0.67 → 0.32 → 0.01；正收益折：80% → 80% → 60% → 40%。
   **没有任何锯齿**。如果「平滑分排序」本身是噪声，这条曲线应该是平的、抖的。
   它单调且陡，说明参数曲面的顶部区域**确实比底部好**——「哪个区域好」这个信息是真的。
2. **但 K 取多少，仍然没有被验证。** 极差 18.4pp，这个量级比任何一条结论都大。
   而且 K 越小越接近「选参」这一端（K=1 就是平滑选参，再往上一格就是事后选参 = +20.7%），
   所以 **K 越小越占便宜是结构性的，不是「K=3 是最优 K」**。
   `k_note` 会主动把极差报出来并提示「别事后挑最好看的 K」——
   事后挑 K 不过是把单点择优从参数挪到了 K 上。
   → **接口上给多条臂并列，就是为了不让读者只看到一个数字。**
3. **最稳、最可放心用的一条：回撤控制与 K 无关。**
   K=5 / 10 / 31 的最差折回撤都是 **−8.4% / −8.3%**，
   而 argmax −15.5%、邻域平滑 −17.9%、默认 −17.9%。
   也就是说「只要做集成，最差的那一折回撤就减半」，这一点**不依赖你选哪个 K**。
   如果你的目标是「别在某半年被腰斩」，这是本节最可靠的结论。
4. **这一版集成同时改进了收益和回撤，与上一版的结论不同——差别就是本节的全部意义。**
   上一版的「全组合集成」是无差别平均 31 组，把已知最差的 momentum 组
   （该组在 31 组里平均夏普最低、半数窗口亏钱）也等权持有了，结果收益平庸。
   限定在好区域内之后，收益从 −1.7% 抬到 +16.7%、回撤从 −15.5% 降到 −8.4%。
   → **「集成」不是万能药；集成什么，决定了集成的价值。**
5. **邻域平滑的作用仍然是「防止一次跨模式翻车」，不是「稳定多赚」。**
   它这次 +6.4pp 里几乎全部来自第 2 折：argmax 选中 `momentum(90日)` 样本外 −5.7%，
   平滑因为 momentum 组整体平庸把它抹掉、落回 ma 附近拿到 +5.2%。
   对比上一版（集成 = 全组合）时它赢得极不平均（−9.3 / +10.9 / 0 / 0 / +4.7 pp），
   这次也一样。**它的价值是降低选参方差，不是提高期望。**
6. **最窄集成臂的构成（ma 10/15 席、momentum 0/15 席）本身就是结构结论。**
   它和「argmax 5 折里 4 折选 ma」互相印证：`ma` 在训练窗的高分是
   **片区性的**（周围邻居也好），而 momentum 的高分是**孤立点**（一平均就掉）。
   这正是「该用 ma、别用 momentum」这条 ✅ 可信结论的第二个来源。
7. **哪怕 +17.2pp 里有一半是运气，换掉 argmax 仍然是对的。**
   argmax 的执行逻辑（挑尖峰）在原理上就是错的，平滑/集成的逻辑
   （不把结论押在一次选择上）在原理上是对的。**做法正确 + 结果不保证**，
   和「做法错误 + 结果偶然很好」是完全不同的两个状态。

**⚠️ 一个必须交代的偏差：邻域带宽不平等**

`off` 在候选里只有 **1 个代表**（它不随择时窗口 × 滞回带展开），
所以 `off` 的邻域只有它自己，**平滑对它等于恒等**，它永远不会被平均拉平；
而 `ma`/`momentum`/`dual` 各组只有 **4~6** 个邻居（实测）。

也就是说：**平滑是偏袒 `off` 的**——不被稀释的那一方天然少挨一刀。
而实测中 `off` 在最窄集成臂里只占 1/15 席、在 argmax 里占 0/5 折。
→ 方向很重要：结论是**逆着这个偏差**得到的，所以「择时有用」比数字看上去更可信。
→ 反过来说，如果哪天结果显示 `off` 明显胜出，要记得它有一条制度性优势，
  别立刻当成「择时无效」的铁证。

**正确的表述方式**

- ✅ 可信：「该用趋势择时，用 `ma`，不要用 `momentum`」——方向性结论，跨折、跨方法稳定。
- ✅ 可信：「做参数集成能把最差折回撤减半」——不依赖 K，跨臂稳定。
- ❌ 不可信：「60 日均线 + 2% 滞回带是最优」——单点最优，跨折完全不收敛。
- ❌ 不可信：「集成就该取前 3 组」——K 的极差 18.4pp，只是这次 K=3 好看。
- 📌 方法论：**结构性结论（用不用、用哪一类）比参数点估计可信得多**。
  想验证前者，把「用/不用」做成一个离散选项丢进搜索空间就够了；
  想验证后者，任何搜索都有过拟合风险，只能靠样本外打分——包括给 K 打分。

**复现本节全部数字**

```bash
.venv/Scripts/python.exe -m quant.main --pool 消费 --strategy momentum --top-n 15 --use-open \
  --benchmark sh000932 --timing-proxy 000932 --start 20200101 --end 20240909 \
  --walk-forward --fw-train 2 --fw-test 0.5 \
  --grid-lookbacks 120 --grid-topn 15 --grid-buffers 0 \
  --grid-timing off,ma,momentum,dual \
  --grid-timing-lookbacks 40,60,90,120,200 --grid-timing-bands 0,0.02 \
  --wf-ensemble-k 3,5,10,0
```

> ⚠️ 注意 `--grid-timing` 的搜索空间必须含 `off`（不给也会自动补）。
> 如果只给 `ma,momentum,dual`，walk-forward 就只能在「这三种择时」里挑，
> 永远得出「择时有用」的结论——这是最隐蔽的一种选择性偏差。
> `tests/test_grid_timing.py` 有专门的测试锁这一条。
>
> ⚠️ `--wf-ensemble-k` 与 `--grid-timing` 同理：**不要把 K 列表缩减成「跑过一遍后
> 最好的那个 K」**。默认 `3,5,10,0` 四条臂并列，是为了让 K 敏感度一眼可见。
> `tests/test_wf_ensemble.py` 锁住了 K 的排序口径（K=1 必须逐折等于平滑臂）、
> K 的有效值上限（K > 候选数时退化为全部）、以及 `parse_ensemble_ks` 的幂等性。

Windows 上直接双击项目根目录的 **`启动网页.bat`** 即可（会自动开浏览器）。

页面上能调什么：

| 区块 | 内容 |
|---|---|
| 选股 | 股票池 / 额外补充代码、因子、Top N、回看窗口、调仓频率、缓冲带、基准、成交价口径 |
| **数据体检** | 池内数据更新到哪天、结束日是不是过时了；「用最新数据」「更新数据」两个按钮 |
| **仓位管理** | 择时模式（`off`/`ma`/`momentum`/`dual`）、均线长度、滞回带、仓位上下限、波动率目标、择时用的代理指数 |
| **样本外验证** | 开关 + 训练窗/测试窗 + 要一起扫的择时模式 |
| **调仓清单** | 我的持仓（每行「代码,股数」）+ 基准日，**独立按钮**，输出「该买/该卖多少股」 |

结果直接出在右侧：

- 8 个指标卡 + 4 张 ECharts 图（净值 / 回撤 / 分年度 / 月度热力图）
- 启用择时后**额外显示平均仓位、在场时间占比、仓位切换次数**
- 跑样本外时出**各做法对比表 + 逐折明细**，并可打开完整 HTML 报告、下载 CSV
- 生成调仓清单时出**动作 / 现价 / 当前股数 / 目标股数 / 本次变动 / 金额**表格，
  并单独提示「哪些持仓因取不到价格而没算出来」

实现上是 `quant/web.py`（FastAPI 后端）+ `quant/templates/index.html`（单文件前端），
后端只把表单翻译成 `python -m quant.main` 的命令行再调用，**不重复实现回测逻辑**——
所以页面跑出来的结果与命令行逐位一致。

### 先看数据新不新，再看清单

**结束日期默认是 `20240909`。** 如果你不改它就直接生成清单，拿到的是
「假如当时是 2024-09-09，该买什么」——回测照样跑通、清单照样漂亮，
但完全不是今天的操作建议。这是这个工具最容易踩的坑，所以页面上做了三层防护：

1. **页面一打开就自动体检**：调 `/api/data_freshness` 读本地缓存（不联网），
   算出池内数据的最新截止日，并与结束日比对。
2. **明确的状态文案 + 一键对齐**：结束日偏离数据超过 5 天就标黄告警，
   并提供「用最新数据」按钮，把结束日期直接改成数据里的最新交易日。
3. **结果区顶部再提醒一次**：点了按钮之后眼睛在右边，只把警告留在左侧小字里
   容易被忽略，所以清单上方会再出现一条横幅。

「更新数据」按钮调 `--refresh-data`（见下），把**整池**标的增量补齐到结束日。
为什么要整池更新而不是只更新用到的：缓存更新只覆盖本次选中的标的，
池里没被选中的股票会一直停在旧日期。实测抽样 30 只里有 15 只停在几个月前，
而它们照样会出现在候选池里，导致清单里混进过期价格——算出来的股数是对的，
但价格不是今天的。消费池 36 只实测 **16 秒**补完。

`--codes` 与 `--pool` 是**并集**，不是二选一。典型用途是把
**002557 洽洽食品**补进消费池——它不在中证主要消费（000932）、可选消费（000989）、
白酒（399997）、沪深300 的任何一个成分股名单里，只能靠手动代码加进来。

### 调仓清单：从「看回测」到「能下单」

`main.py` 的持仓分支是**独立 return** 的（不会产出净值曲线），所以页面上它是
**单独一个按钮**，跟「运行回测」二选一，不能在一次调用里兼得。

- 持仓文本框留空 → 自动用项目根目录的 `my_holdings.csv`
- 文本框格式很宽松：逗号 / 空格 / 分号 / 制表符都能分隔，支持 `#` 注释行，
  代码不足 6 位自动补零（直接粘 `600519 100` 也能用）
- 想要能落地的清单，先点「用最新数据」把结束日期对齐到最近交易日

> ⚠️ 三个已知限制：
> 1. **同步执行**：一个请求会一直挂着直到回测结束。普通回测约 15 秒；
>    样本外验证 20 秒到几分钟，取决于扫多少组以及数据是否已缓存。
> 2. **样本外的选股网格被钉死在页面上填的那组参数上**，只让「择时」这一维去扫。
>    不这样钉会套用 CLI 默认的 4×3×2=24 组选股网格，再乘择时组合 → 几百组、一跑几小时。
> 3. 只监听 `127.0.0.1`，同局域网的其它机器访问不到。

安全：`/report/{file}` 与 `/download/{file}` 只允许读项目根目录下
`.html` / `.csv` 文件，路径穿越（`../`、子目录）会直接 404，`tests/test_web.py` 有覆盖。

### 一个「点了有反应」的 bug：预设按钮曾经全部失效

页面上那排预设按钮（`消费·加择时 ma60`、`沪深300·加择时 dual`、`消费·样本外验证` 等）
调 `fillPreset()`，早年写的是 `$('lookback').value = lookback`。
但那几个 input **只有 `name` 没有 `id`**，`$()` 返回 `null`，赋值当场抛 `TypeError`：

```
$('pool').value = pool;              // OK
$('pool').dispatchEvent(...);        // OK
$('strategy').value = strategy;      // OK
$('lookback').value = lookback;      // ← 抛异常，后面全不执行
```

后果是 `top_n` / `rebalance` / `benchmark` 一个都没设上，而
`fillTimingPreset` 里的择时参数**从来没生效过**。之所以长期没人发现：
池子和因子确实切了，按钮「有反应」。

修法是两处一起改——补齐 `id`，并把 `fillPreset` 改成走
`document.forms.runForm`（按 `name` 取字段）。后者更关键：按 `name` 取，
字段一定存在；按 `id` 取，漏写一个 `id` 就是静默失效。

`tests/test_web.py` 里加了 5 条**静态契约测试**锁住这类问题：
JS 引用的 `id` 必须在 HTML 里存在、JS 读的表单字段必须存在、
`onclick` 指向的函数必须已定义、前端 fetch 的 `/api/*` 必须在 `web.py` 里注册。
这类错误在浏览器里不报错，只表现为「点了没反应」，靠人眼 review 基本抓不到。

## 已发现的关键洞察

### 1. pandas 3.0 的 `rebalance_flags` breaking change
`PeriodIndex != PeriodIndex.shift(1)` 在 pandas 3.0.5 返回**全 True**，会让所有"月度调仓"变成"每日调仓"。

**修复**（`quant/strategy.py`）：用 `~period.duplicated(keep="first")`。

**影响**：在 pandas 3.0 下报告过的所有"月度/周度"回测结果都需要重跑。

### 2. reversal_20 在 A 股是个常被忽视的稳健策略
- 沪深300 reversal_20：+140.5% / 夏普 0.82 / 回撤 -35.9%
- 消费 reversal_20：+56.7% / 夏普 0.52 / 回撤 -38.5%
- 比动量更稳——尤其在 2021 年牛市后的熊市里

### 3. low_vol_60 是抗跌神器
- 沪深300 low_vol_60：+19.8% / 回撤 -16.0% ← **回撤只有其他策略的 1/2**
- 适合"防守型"配置

### 4. 沪深300 vs 消费池的熊市表现相反
- 消费动量在熊市**跌得少**（超额 +5.8%）
- 沪深300 动量在熊市**跌得更多**（超额 -5.0%）
- **沪深300 动量在熊市应该减仓**

### 5. 多池组合 ≠ 越多越好
- 消费+医药（2池）：+53.4%
- 消费+白酒+医药（3池）：+36.1%（白酒 ma_trend 拖后腿 -11%）
- HS300+消费+医药（3池，但每池用对策略）：**+68.3%**
- **关键：每个池子用对的策略 + 板块间分散**

### 6. 择时是风险控制器，不是收益增强器
- 无论用哪个参数，择时都稳定地把波动从 25.8% 压到 12.5%~20.7%、回撤从 −41% 压到 −23%~−40%。
  **这份确定性来自机制（仓位小 → 亏得少），不来自预测能力。**
- 但收益能否保住高度依赖参数：ma60 三项全改善，ma120 夏普持平，ma200 三项全退步。
  同一策略同一段样本，只换均线长度结论就翻转。
- 波动率目标用错会变成纯负担：目标 15% 远低于该池自身 25.8% 的波动 → 长期只放 68% 仓位
  → 在长期上涨的资产上直接减收益（40.4% → 0.7%）。**目标波动率要接近策略自身波动才有意义。**
- 另一个容易忽略的坑：仓位信号若逐日变化并直接乘到权重上，月频策略会退化成每天全仓对倒
  （实测 17041 笔订单）。仓位必须与调仓节奏对齐。
- **样本外把择时参数一起搜之后**：模拟「选不选择时、选哪类」这件事是**结构性的、可信的**
  （5 折里 4 折选 ma，样本外 −0.5% 对不择时 −15.9%）；而「哪个窗口+哪个滞回带最优」
  是**拟合的**（滞回带 0 与 2% 五折各半）。详见 9.1。

### 7. 事后选参的幻觉会随搜索空间膨胀，但样本外成绩不会
同一段消费池样本、同一套 walk-forward 设定（2 年训练 / 0.5 年测试）：

| 搜索空间 | 事后选参（全样本最优固定） | Walk-Forward 自适应 | 幻觉缺口 |
|---|---|---|---|
| 4 组（只搜 lookback × top_n × buffer） | −7.8% | −12.6% | **4.8pp** |
| 31 组（再 × 择时模式 × 窗口 × 滞回带） | **+20.7%** | −0.5% | **21.2pp** |

搜索空间扩了 7.75 倍，事后选参的数字涨了 28.5pp，而诚实的样本外成绩只涨了 12.1pp。
**每加一个参数维度，你能报告的「最优回测」就好看一截，但其中能迁移到实盘的比例在快速下降。**
所以看到「加了 N 个参数后策略变强了」时，第一反应应该是：净增的收益里，有多少是搜索空间本身贡献的。

**推论：不只「参数」会被事后挑选，「选参方式」和「集成度」同样会。**
在 31 组那个搜索空间上，把集成度 K 从 3 换到 31，样本外总收益从 +16.7% 掉到 −1.7%
（同样这批测试窗，**极差 18.4pp**）。如果只报最好的那个 K，得到的就是一个过拟合数字——
只是这次挑选发生在「用哪个 K」而不是「用哪个参数」上。
所以 `--wf-ensemble-k` 默认并列 4 条臂、并把极差主动打印出来（见 9.2、已知坑 18）。

**反过来说，K 曲线单调这件事本身就是信息。**
16.7% → 12.6% → 4.1% → −1.7%（K=3/5/10/31）单调下降、无锯齿；
若「平滑分排序」纯属噪声，这条曲线应该是平的、抖的。
它单调且陡，说明参数曲面**顶部区域整体优于底部区域**——
这类「区域级」结论，比任何一个参数点估计都可信。

## 已知坑

1. **pandas 3.0 + akshare 在 miniconda 下行为不同**——本项目所有回测必须在 `.venv` 下验证（pandas 3.0.5 / akshare 1.18.94 / numpy 2.5）。
2. **akshare qfq 复权基点会随区间变化**——所以「往前补头」不能增量拼接，必须**全量重拉后覆盖**。数据层现在这样做，并用 `data/_coverage.json` 记录「已验证的起始日」，避免每次运行都重复回补。
3. **akshare 网络不稳**：东财 push2his.eastmoney.com 偶尔断连（`RemoteDisconnected`），但 Sina 一般稳定；某些网络环境下 `www.bse.cn`（北交所）会被代理直接拒绝。全市场池构建已做多源降级，单个源失败不影响整体。遇到 "跳过 XX 只" 可重跑让增量补齐。
4. **价格过高的股票无法 100 股卖出**：例如清仓 6.67% × 100 万 = 6.67 万 = 茅台 51 股 < 100 股——工具自动跳过该笔并在清单中标记为 0 股。
5. **本工具只产出清单，不直接连券商下单**——实盘前必须自己核对并手动下单。
6. **涨跌停判定必须与成交价同口径**：按收盘价成交就用收盘价判（封板/一字板），按次日开盘价成交就只用**开盘价**判。
   混用等于用买入时还没发生的信息决定能不能下单（前视偏差）。`filters.tradability` 的
   `exec_at_open` 与 `factor_weights` 的 `exec_shift` 就是为此存在的，改调用链时不要漏传。
7. **「一字板」的判据方向不同**：涨停看 `low`（全天没跌破），跌停看 `high`（全天没涨破）。
   两个方向用同一字段会把「开盘跌停后拉起」误判成一字跌停——本项目真实踩过这个坑
   （002157 于 2020-02-04 开盘 10.57 跌停、最高 11.68、收 11.48）。
8. **权重矩阵里绝不能出现 NaN**。末尾的 `ffill()` 把 NaN 解释成「沿用上期持仓」，
   所以任何一行只要有 NaN，那一列就会一直持有下去、永不卖出。
   真实踩过：某次改动让 `_allocate` 只返回入选股票的权重（未补全 0），
   结果 13 次调仓 382 笔订单里 **0 笔卖出**，回撤凭空变大。
   新增权重方案时必须 `.reindex(score.columns).fillna(0.0)`。
9. **`inv_vol` 必须取倒数**。写成 `vol / vol.sum()` 会变成「波动率越大权重越大」，
   与风险平价方向完全相反。也已踩过（高波动票拿到 57% 仓位），现有单测锁死。
10. **最低佣金要按「笔数」算**：佣金下限是对每一笔委托成立的，
    不是对当日成交额汇总成立。写成 `max(当日总成交额×费率, 5元)` 就永远不生效。
11. **市值必须用真实成交均价**：缓存里的收盘价是前复权价，
    乘流通股本会系统性低估早期市值（复权价随时间被整体缩放）。
    正解是 `成交额 ÷ 成交量 × 流通股本`——这两个字段本地缓存里都有，无需联网。
12. **成本敏感度**：把 `--slippage` 从 0 调到 5bp、加上 5 元最低佣金后，
    消费池同期总收益从 42.2% 掉到 40.4%。换手越高的策略、本金越小的账户，
    这项影响越大。对比历史结果时务必确认成本口径一致。
13. **仓位信号必须与调仓节奏对齐**：择时敞口若逐日变化并直接乘到权重上，
    月频策略会退化成「每天全仓对倒」——实测 1125 次调仓 / 17041 笔订单，
    成本吃掉全部收益。默认 `--timing-update rebalance` 已修正（订单降到 1025）。
    写任何「组合级缩放」逻辑时都要先想清楚它会不会制造出计划外的交易。
14. **择时的因果性**：敞口序列与目标权重同索引，只能用 `close[t]` 及更早的信息。
    滚动均值 / 滚动波动率在 t 处取的是 t-N+1..t 的窗口，合法；
    但任何 `shift(-k)` 都会造成前视偏差，且净值会好看得离谱而不会被别的检查发现。
    `tests/test_timing.py` 有专门的因果性测试（篡改未来不影响过去）。
15. **`--grid-timing` 的搜索空间必须含 `off`**：只给 `ma,momentum,dual` 时，
    walk-forward 只能在「三种择时」里挑，永远得不出「不如不择时」的结论——
    这是最隐蔽的一种选择性偏差（把对照组从候选里删掉，等于预设了答案）。
    代码会自动把 `off` 补进去，`tests/test_grid_timing.py` 有专门的测试锁这一条。
16. **`off` 组合不能跟着 `timing_lookback × timing_band` 一起展开**：
    不择时时窗口取 60 还是 200 完全等价，跟着展开会让同一个策略在网格里重复出现 N 次，
    把「按择时模式分组的平均夏普」这类统计搅浑（等价样本被当成独立样本加权）。
    同理，`--grid-timing` 会让预热期自动延长到最长候选窗口，
    否则长窗口组合在样本开头会因均线历史不足而被迫空仓，被误判成更差。
17. **`parse_ensemble_ks` 必须对自己幂等**：`main.py` 先解析一次 `--wf-ensemble-k`，
    再把结果传给 `walk_forward_search`，后者内部还会再解析一次。
    早期版本对已解析的 `(3, 5, 10, None)` 会 `int(None)` 抛 TypeError——
    单测只喂过字符串所以没暴露，直到 `--walk-forward --wf-ensemble-k 3,5,10,0` 实跑才崩。
    **教训：解析函数要能吃下自己的输出，测试要覆盖「字符串」和「已解析结构」两条路径。**
18. **集成度 K 是「事后选择的入口」，不能让报告只显示一个数字**：
    K 越小越接近「单点择优」（K=1 就是按平滑分选参），天然更容易贴近事后选参的上界。
    实测同一批测试窗上 K=3 与 K=31 的样本外总收益差 **18.4pp**，
    比这一节任何一条结论的量级都大。所以 `--wf-ensemble-k` 默认给 4 条臂并列、
    并且 `k_note` 会主动报出极差、提示「别事后挑最好的 K」。
    只报最优 K 的报告，读者看到的就是一个过拟合数字。
19. **邻域平滑对 `off` 有制度性偏袒**：`off` 在候选里只有 1 个代表
    （不随窗口 × 滞回带展开），其邻域只有自己 ⇒ **平滑对它等于恒等**，永不被稀释；
    而 `ma`/`momentum`/`dual` 各组只有 4~6 个邻居，会被平均拉平。
    也就是说平滑偏向「不择时」这一侧。实测中 `off` 在最窄集成臂里仅占 1/15 席，
    说明「择时有用」的结论是**逆着这个偏差**得到的（更可信）；
    反之若某次结果显示 `off` 胜出，要记得它有这条制度性优势，别直接当成择时无效的铁证。

## 方法论修正记录（P0）

以下三项是「会让回测结论本身失真」的问题，已修复。它们不影响功能，但影响可信度。
（P1 的六项严谨性修正见后文。）

### P0-1 幸存者偏差 → 成分股时点化

**问题**：指数成分股接口返回的是**当前**成分股。用它回溯历史等于只在「今天还活着的公司」里选股，
后来被剔除/退市暴跌的股票从未进池，收益被系统性高估。

**修复**（`quant/universe.py`）：
- 每次拉取成分股自动归档快照 `data/cons_snapshots/cons_<指数>_<日期>.csv`，逐日积累时点历史；
- `--as-of` 按历史时点取成分股；无可用快照时**显式告警**并给出缓解建议，绝不静默放行；
- `--pool all` 全市场建池（含已退市，多源降级获取），从构造上消除该偏差；
- `--min-listed-days` 按上市自然日剔除次新股（避开新股连续一字板与无涨跌停限制期）。

### P0-2 判定口径与成交价错位 → exec_at_open / exec_shift

**问题**：统一用收盘价判定「能否成交」，但 `--use-open` 时实际按开盘价成交。
等于用买入时还没发生的信息决定能不能下单，属前视偏差。两处错位：
1. 涨跌停判定用收盘价 → 改为按成交价判定（`filters.tradability(exec_at_open=...)`）；
2. 调仓决策在 t 日、成交在 t+1 开盘，可交易性却取 t 日 → 新增
   `factor_weights(exec_shift=...)`，把可交易性面板后移到**成交当日**。

### P0-3 涨跌停判定粗糙 → 改用涨跌停价 + 一字板识别

**问题**：旧实现比 `close.pct_change() >= 涨跌幅度 - 0.5%`，既无法识别一字板，
又因容差过宽而误禁（实测消费池 36 只 × 1320 日中，误禁买 15 次、误禁卖 11 次）。

**修复**（`quant/filters.py`）：由前收盘价推出涨跌停**价**（分位四舍五入），
再用 open/high/low/close 与之比较，区分「收盘封板」与「一字板」；
判据方向按方向区分（涨停看 low、跌停看 high）。

**影响**：消费池 2020-01-01~2024-09-09 同参数对比，修复后总收益 43.60% → 42.23%、
夏普 0.441 → 0.433、超额 68.6% → 67.0%。方向正确（去掉的是虚增部分），
但幅度不大——因为消费池都是流动性好的大盘股，很少触及板。
**换成小盘池或 `--pool all`，差异会显著放大。**

## 严谨性修正记录（P1）

P0 修的是「结论会不会错」，P1 修的是「结论会不会被打折」。六项全部落地。

### P1-1 成本模型 → 滑点 + 最低佣金 + 冲击成本

**问题**：只算佣金和印花税。月频换手 10 只票，滑点通常吃掉 1~3%/年；
且佣金没有「单笔最低 5 元」约束——低本金下这一项比费率本身更重要。

**修复**（`quant/backtest.py`）：成本拆成四块
```
佣金     = max(成交额 × 费率, 笔数 × 最低佣金)   ← 必须按笔数，不能按当日汇总额
印花税   = 卖出额 × 税率
滑点     = 双边成交额 × 滑点率                   ← 新增，默认 5bp
冲击成本 = coef × sqrt(该票成交额 / 该票 ADV)     ← 新增，默认关闭
```
新增 `cost_kwargs()` 统一六个入口的取参，杜绝「主回测算滑点、网格搜索不算」的口径分裂。

**影响**（消费池 2020-01-01~2024-09-09 同参数）：
总收益 42.23% → **40.42%**，夏普 0.433 → **0.422**，超额 67.0% → **64.9%**，
成本年化拖累 **0.57%**。改用 `--slippage 0 --min-commission 0` 可回到旧口径。

```bash
--slippage 0.0005        # 单边滑点，默认 5bp
--min-commission 5       # 单笔最低佣金（元），默认 5
--impact-coef 0.1        # 平方根冲击模型，0=关闭
```

### P1-2 成交量约束 → 按 ADV 限制单票权重

**问题**：回测假设「想买多少都买得到」。小市值票实际吃不下大仓位，
一次性吃掉某只票当日 30% 成交额时，回测里假设的成交价根本拿不到。

**修复**：`filters.capacity_cap()` —— 单票权重上限 = 参与率 × 20日均成交额 / 本金。
超出部分按比例再分配给未触顶标的（注水法），全部触顶则**留现金**，不强行满仓。

```bash
--max-participation 0.05    # 参与率 5%，0=不限
--min-amount 50000000       # 金额口径流动性门槛（比 --min-volume 更合理）
```

> 本金 100 万时对消费类大盘股不构成约束；把 `--capital` 调到 1 亿以上才会显现。

### P1-3 因子中性化 → 行业 + 市值

**问题**：动量因子在 A 股同时是一个小市值因子。小盘股暴涨的行情里，
你以为赚的是「动量」，其实赚的是「小盘 beta」——行情切换时原样还回去，净值曲线上完全看不出来。

**修复**（`quant/neutralize.py`）：每个交易日内先减行业均值、再减市值分组均值。
市值用 **真实成交均价（成交额÷成交量）× 流通股本**，而不是前复权价×股本
（后者会系统性低估早期市值）。行业映射走新浪行业（49 个），缓存 30 天。

```bash
--neutralize industry,size
```

> 单行业池（如「白酒」）做行业中性化只是全体平移，**不改变选股结果**——池子里本来就没有行业差异。

### P1-4 因子有效性 → IC / IR / 衰减 / 分组收益

**问题**：净值上涨 ≠ 因子有效。可能是运气、可能是 beta、可能是过拟合，
三者从一条净值曲线上无法区分。

**修复**（`quant/factor_eval.py`）：直接回答「分数靠前的股票是否真的跑赢」。

```bash
--factor-eval
```

指标刻度：`|IC| < 0.02` 基本无效 / `0.03~0.05` 可用 / `> 0.1` 先排查数据泄漏。
**IR（IC均值÷IC标准差）比 IC 均值更该被重视**——IC 均值 0.05 但波动 0.3 的因子实则不可用。
分组收益的**单调性**比 IC 更难伪造：只有最高组一枝独秀时，收益多半由少数个股贡献，实盘复制不到。

消费池实测（2020-2024，未来 20 日收益）：

| 因子 | IC均值 | IR | 正IC占比 | 评价 |
|---|---|---|---|---|
| momentum(120) | 0.0425 | 0.159 | 58.2% | 有效可用 |
| low_volatility(60) | 0.0504 | 0.192 | 56.2% | 强有效 |
| reversal(20) | 0.0127 | 0.054 | 53.5% | 基本无效 |

### P1-5 权重方案 → 波动率倒数 / 分数加权 / 单票上限

**问题**：`1/len(picks)` 硬编码等权，集中度无处约束。

**修复**（`quant/strategy.py`）：

```bash
--weighting inv_vol      # equal(默认) / inv_vol 波动率倒数 / score 分数加权 / rank 排名加权
--max-weight 0.2         # 单票上限，超出部分注水式再分配，全触顶则留现金
```

`inv_vol` 是风险平价在忽略相关性时的实用近似：低波动票拿更多权重，组合的事前波动更均衡。

### P1-6 样本外验证 → walk-forward

**问题**：`--grid` 是全样本网格搜索，即「事后选参」+「多重比较」。
试的组合越多，碰巧最优的那个越漂亮——这是纯粹的噪声。
表现是训练期夏普 1.2、实盘立刻掉到 0.3。

**修复**（`grid.walk_forward_search`）：把样本切成「训练窗 + 紧邻测试窗」，
训练窗内选参、测试窗内**完全不改参**，把各测试窗收益连乘成一条真实可得的曲线。
同时给出两个对照组：**全样本最优固定参数**（事后选参的上界幻觉）与**默认参数**（不调参）。

```bash
--walk-forward --fw-train 2 --fw-test 0.5 --fw-metric sharpe
```

消费池实测（2020-01~2024-09，5 折）：

| 参数策略 | 样本外总收益 | 年化 | 平均夏普 | 正收益折占比 |
|---|---|---|---|---|
| Walk-Forward 自适应 | −12.6% | −5.1% | −0.26 | 40% |
| 全样本最优固定（事后选参） | −7.8% | −3.1% | −0.07 | 60% |
| 默认参数（不调参） | −10.7% | −4.3% | −0.22 | 40% |

**事后选参在样本外比自适应选参「好」4.8 个百分点——这 4.8pp 就是幻觉的量化值。**
更值得注意的是：5 折里每一折选出来的都是 `lb=120 n=10`（即默认参数），
说明这个网格上根本不存在比默认更好的参数，调参空间是空的。

## 进阶用法

### 自定义因子
在 `quant/factors.py` 加新函数 → 在 `quant/compare.py` / `quant/daily.py` / `quant/combine.py` 的策略路由里注册 → 即可通过 CLI 使用。

### 自定义股票池
在 `quant/universe.py` 的 `INDEX_POOLS` 里加新映射：
```python
INDEX_POOLS["工程机械"] = "000xxx"  # 工程机械指数代码
```
或者用 `concept:xxx` 直接拉概念板块。

### 自定义 webhook
`quant/daily.py` 的 `send_webhook` 是个简单 POST——飞书/钉钉/企业微信机器人都支持自定义 JSON 格式，按需修改 payload 即可。

### 仍未做（按价值排序）

1. **CLI 能力继续上页面**——`quant/combine.py`（多池组合）、
   `quant/attribution.py`（风险归因）、`quant/rolling.py`（滚动回测）、`quant/daily.py`（每日监控 + webhook）
   都已在命令行跑通，但 Web 上没有任何入口。因子评价、多策略对比已接出，其余按价值分批接。
2. **回撤熔断 / 止损**——目前只有「趋势档位」这种粗粒度的风险开关，
   没有基于组合自身回撤的熔断（如「回撤超 15% 后强制降仓」）。
   注意它和择时是两件事：择时看的是市场趋势，熔断看的是自己亏了多少。
2. **集成按模式加权，而不是严格按 K 截断**——现在是在「平滑分前 K 组」内等权，
   K 仍是硬阈值（K 之外一组不持有，K 之内同等权重）。
   更平滑的版本是按模式组均值加权（ma 权重高、momentum 权重低）
   或按平滑分做指数加权，这样「区域好坏」是连续用上的，不存在一个硬 K。
   注意：任何新方案都必须同样把「K / 温度」当作**一维并列参数**报出来，不能只报最优。
3. **协方差感知的权重**——`inv_vol` 只用了对角阵（忽略相关性）。真正的风险平价需要协方差矩阵估计。
4. **多因子权重自动寻优**——现在 `--factors momentum=1,low_volatility=0.5` 的权重靠手调，
   可以用 IC 加权或最大化 IC_IR 来定。
5. **行业映射覆盖率**——新浪行业只覆盖约 50% 的 A 股（2985/5923）。
   未覆盖的标的不会被行业中性化，做全市场中性化时需注意。
6. **工程化**——`main.py` 仍是 40KB 单文件，该拆成 cli / pipeline / output 三层；
   Web 层用 `subprocess` 同步跑长任务会阻塞。
7. **体验债**——默认结束日是否改成最近交易日；「一键今日清单」按钮；
   Chrome 无头截图做成回归测试；README 加截图 / GIF。
